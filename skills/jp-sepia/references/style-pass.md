# Pass 3 — 表層の文体（日本語）

構造が直ってから最後に走らせる。根拠: LAMP/CHI 2025（L。編集操作の比率）、Reinhart et al. PNAS 2025（P）、Russell et al. ACL 2025（R）、Shaib et al. slop taxonomy（S）、Zaitsu & Jin 2023（Z）、humanizer-jp（H）、180 本測定（K）、英語 35 パターンの日本語仕分け（Port）。編集は **置換 74% / 削除 18% / 挿入 8%**（L）。迷ったら切る。増やしてよい唯一の修正は、実在する具体である。

英語版の検出語を訳して使わない。実測 1 位は「適切な／適切に」であり、「浮き彫りにする」は 180 本で 0 回だった（K）。感覚の禁止リストは当たらない。

## 0 文体を固定する（日本語の機械判定ができる層）

同一文書の地の文で敬体と常体を混ぜたら即修正（Port）。台詞の役割語、引用、コード、固有名は別勘定。

| 会場 | 既定 |
|---|---|
| 対外告知、顧客向け、Qiita / Zenn の多くの記事 | 敬体 |
| 社内技術メモ、論文調、小説の地の文の多く | 常体 |
| PR / Issue、チケット | 会場の直近。無ければ常体寄りで短い |

丁寧語の密度そのものは指紋ではない（H: 人間ブログの方が丁寧語は多い）。崩して「人間らしく」見せるな。

敬語は会場のレジスタに合わせる。顧客メールの「お世話になっております」は容器であり、指紋ではない。チャットボットの在庫（「お役に立てれば幸いです」「ご質問があればお気軽に」）は指紋である。区別は professional-pass #1。

## 1 編集者が実際に直した七つの遺物（L。優先順）

| # | 遺物 | 直し |
|---|---|---|
| 1 | 語の選択が場違い（28%） | レジスタを外した漢語、カタカナ、過剰な漢語名詞を、その場の語へ戻す。「〜することができる」→「〜できる」。不確実でないなら「〜と思われる」を動詞そのものへ |
| 2 | 文の構造が悪い（20%） | 連用中止で何段も繋いだ文を、二つに割る。一つの絡まった思考は二つの平明な文 |
| 3 | 重複する説明（18%） | 場面がすでに示していることを消す。「[主節]、それにより〜」の尻尾は読点から後ろを切る |
| 4 | 陳腐（17%） | その場の言葉へ替える。**より平坦な言い換えへ逃げるな**（記録された機械の失敗）。新しい言葉が無ければ行を消す |
| 5 | 具体の欠如 | 唯一の加算。実在の名、物、数、行為。材料が無ければユーザーに聞く。汎用の描写を足すと悪化する |
| 6 | 紫の散文 | 短く具体へ。「彼女は、言いようのない哀しみの淵で……」→「泣いた。不公平で泣いた。楽にならなかった。」 |
| 7 | 時制・アスペクトの迷い | 段落内の「〜していた／〜する／〜した」の漂流を止める |

## 2 狩る構文

英語の POS テンプレ（a mix of / the weight of / 分詞の尻尾）は日本語に無い。代わりに、日本語で密度が上がる型を狩る。一発は判決にならない。**スロップは累積**（S）。固まったら書き直す。

| 型 | 例 | 直し |
|---|---|---|
| 対比の公式（Port: 日本語で最も密） | XではなくY / XのではなくY / Xではない。Yだ / XどころかY / XというよりY / Xではなく、むしろY / XじゃなくてY | 意味している一方だけ言う。八形を合算して密度を見る |
| 三点セット | 効率的で、革新的で、持続可能な | 二か四。リズムを折る |
| 「〜という」の連鎖 | 300–400 字に 3 回以上（Port） | 一つ残して他は名詞か「その」へ |
| 主語の再復元 | 省略できる主語が 4 段落以上連続で明示（Port。英語 #13 の逆） | 文脈から取れる主語を落とす |
| 読点過密 | 1 文に読点 4 つ以上が、同一文書に 2 文以上（Port） | 文を割る。読点ゼロの短文を残す |
| 体言止めの連続 | 4 文以上続く | 一つ残し、他は普通の述語へ。アクセントとしての体言止めは 2 文連続まで |
| 翻訳調の受身 | 「〜されることが可能である」「〜によって〜が行われる」 | 動作主が分かるなら能動。日本語の自然な受身（迷惑の受身など）は残す |
| 接続詞の接着 | 文頭の「一方」「つまり」「さらに」「また」「これにより」「加えて」が段落の糊 | 接続詞を外して並置する。残すなら種類を散らす。「これにより」はリトマス（Rapls） |
| 全角ダッシュ | 「Claude Code——Anthropic の CLI——を使えば」（GPT に厚い） | 括弧か読点。検出時は `—` `–` `――` `──` `━━` も見る。コードや表の区切りは除外 |

コードブロック、インラインコード、Markdown 表、コマンド／パス／オプション一覧、用語集の「用語 — 定義」、参考リンク行は、密度カウントから除外する（Port）。

## 3 語彙

実測で残った語を先に見る。感覚で足した語は下の「感覚リスト」に分離する。ヒットは 1,000 字あたりの密度で見る。長い人間記事は生カウントで AI と並ぶ（K）。

### 実測上位（K, 180 本。1 記事あたり生カウント）

| 語 | 1 記事あたり | 直し |
|---|---|---|
| 実現する | 1.08（リスト外だったが単独トップ） | 何が、いくら、どうなったかを書く |
| 適切な／適切に | 0.59 | 何が適切かを書くか、語を落とす |
| 重要な／重要です | 0.34 | 重要だと宣言せず、事実を置く |
| 本記事では | 0.27 | 切って本題へ |
| 〜を活用する | 0.23 | 「使う」「入れる」か、何に使ったかを書く |
| 不可欠 | 0.16 | 無いと何が壊れるかを書く |

### 談話の型（H。Claude 素のトーンで検証済み）

| AI が厚い | 性質 | 人間側 |
|---|---|---|
| 〜を整理すると／整理しておきたい | まとめたがり | 「要するに」「ざっくり」、または前置きごと削除 |
| 〜しておきたい／〜しておきます | 配慮の前置き（人間ほぼ不使用） | 「〜する」と言い切る |
| 〜といえます／〜といえるでしょう | 評価まとめの常套 | 「〜だ」「〜だと思う」、または評価文ごと削る |
| 高い水準で実現されている | 評価ヘッジ | 事実と数字へ |
| 文頭の「一方」「つまり」 | 論理の明示しすぎ | 接続詞を落とす |
| 〜ではないでしょうか | 婉曲ヘッジ | 「〜だ」「〜だろう」 |

「地味」「けれど」も AI に寄るが、文脈で自然なら無理に消さない。

### 感覚リスト（実測で稀、または未測定。クラスタでのみ見る）

包括的、多面的、多角的、促進する、取り組み、ソリューション、最適化、シームレス、さまざまな、効率的な（根拠の数字が無いとき）、可能性を秘めている、という観点から、期待されます。これらは目立つので記憶に残る。頻度の本体ではない。単独ヒットで切るな。

### フィクションの在庫（英語 F リストの日本語対応。小説だけ）

胸がざわつく、喉がからから、雨が気持ちを洗い流す、桜が散るを心情字幕にする、声が鈴を転がしたような／絹のような、目が細くなる／光る、思わず、心臓が跳ねる、背筋が凍る、オゾン、ペトリコール。「……」の連打で余韻のふりをする（地の文の三点リーダ自体は人間側。H）。

## 4 戻す人間側のレジスタ

instruct-tuned モデルはこれらを系統的に抑える（P: 人間比 13–80%）。ジャンルと筆者の声が許す範囲で、散らす。注がない。

| 戻す | 例 |
|---|---|
| 平明な因果 | 「なので」「だから」。漢語の「従って」「そのため」ばかりにしない |
| 否定 | 「返事はどれも足りなかった」。合成否定は人間の半分 |
| 終助詞・談話粒子 | 「ね」「よ」「さ」、ただし会場が許すとき。全文化は別の指紋 |
| 一人称と問い | 視点が許すなら |
| 粗い語 | レジスタが本当に求めるとき |
| 三点リーダ | 余韻として人間の方が使う（H）。装飾の連打にはしない |
| 読点ゼロの短文 | 「無理だった。」「オセロです。」 |

## 5 ジャンル合わせ

表層の AI っぽさの半分はレジスタの不一致である。instruct モデルはジャンルを問わず、名詞が多く、情報密度が均一で、同じ研磨の散文を出す（P）。直す前に目標レジスタを言う（純文学／娯楽／YA／エッセイ／技術解説）。脱 AI したスリラーと脱 AI した純文学が同じ声になってはいけない。文長の分散、漢語率、敬体の選択はジャンル変数であり、普遍定数ではない。

ひらがな率を「AI は高い（H: 0.48 vs 0.30）」という理由だけで漢字へ寄せない。ジャンルで符号が変わる（H）。噛み砕きすぎて緩いときだけ締める。

## 6 音読試験

文法は正しいが口に出せない文は、独立したスロップ次元である（S: "the earthen area that formerly held the puddle was now dry"）。対話と、自分が直した文を音読する（心の中でよい）。母語話者が手紙に書かないなら、話し言葉の形へ戻す。

## 7 偽陽性のホワイトリスト

過修正はそれ自体が指紋である。直すな。

| AI の証拠ではない | 理由 |
|---|---|
| 正しい文法ときれいな句読点 | きれいに書く人間は多い。誤字の注入は検出される仕掛け |
| 敬体そのもの | 人間ブログの方が丁寧語は多い |
| 技術文書の箇条書き・見出し・太字 | 収集条件の差であり、言語的指紋ではない（H）。読者体感としては「3 行ごとに見出し」は臭い。媒体に応じて地の文へ戻す判断であり、検出の自動ヒットではない |
| 漢字の多さ／受身 | ジャンルで向きが変わる |
| 三点リーダ | 人間側 |
| 「一方」や「適切な」の一発 | クラスタだけ数える |
| 正式な場の敬語、Changelog の見出し | 会場一致が、無理な口語に勝つ |
| 引用された台詞、作中文書、コード | 引用は手触りを保つ |
| 筆者本人の確認済みの癖 | サンプルが「また」を使うなら残す |
| 普通の文 | 隙間は人間。すべての行を個性へ研がない |

> 口語は偽装にならない。今世代のモデルはくだけたレジスタをすでに真似る。専門家検出器は「くだけているが、他は完全に機械型」を即座に AI と読む（R）。表層の直しは、Pass 1–2 が先に終わっているときだけ持つ。
